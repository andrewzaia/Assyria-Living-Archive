# Editorial governance starter records

`/governance/` is generated from `governance_page.py` and `data/editorial-revisions.json`.

The data file distinguishes curated **merged project changes** from **public correction notices**. It is not an exhaustive Git history. Each published change has a real immutable GitHub merged commit, an associated pull request, affected pages, an explicit limitation and a review level. A merged pull request means a documented release, not independent peer review. The initial public corrections list is deliberately empty: there are no confirmed and publicly logged correction cases. That is not evidence that no errors exist.

The two original Markdown worksheets in this directory are blank local planning aids. They cannot submit a report or approve a release. Keep contact details, private criticism, unpublished interview information and working consent documents out of public Git.

## Maintenance policy

1. On every substantive editorial change or major public release, update the affected article, evidence mappings, source records, claim-review anchors and the main roadmap. Record a durable public revision entry when its actual merged commit ID is known.
2. For a genuine correction, clarification or withdrawal, create an explicit notice with affected article, original issue, documented action, evidence and the revision ID. Do not present a pending report as a confirmed mistake or a completed correction. Sensitive reports remain private.
3. Use `automated-validation-only` unless independent historical review or other editorial checking has truly occurred. Independent status requires named qualified reviewer, scope, review note and date, with appropriate permission for public attribution. A contribution, citation or automated test is not that review.
4. The public archive currently has no enabled private intake, secure interview custody or functioning correction delivery service. Never claim that clicking Download submits a report.
5. The repository Git history remains the full machine-readable change trail. The curated ledger highlights major delivered steps and public corrections, with links to original commits and pull requests.

This governance policy is informed by COPE's post-publication correction guidance and independent heritage custodians. COPE is not the archive's accreditor or publisher. Source-based historical interpretation, biblical study and community rights require their own domain-appropriate review.
